# Сводный ОПиУ по всем маркетплейсам — `opiu_all.py`

Скрипт-оркестратор по очереди запускает отчёты Ozon, Wildberries и Яндекс Маркета, сопоставляет их статьи с **единым планом статей** и собирает один Excel.

## Четыре файла запуска

| Файл | Что собирает | Спрашивает при запуске |
|---|---|---|
| **`Обновить_отчёт.bat`** | ОПиУ по месяцам (`opiu_all_*.xlsx`) и юнит-экономику по артикулам (`unit_economics_*.xlsx`) | месяц юнит-экономики |
| **`Юнит_экономика.bat`** | Только юнит-экономику по артикулам за один месяц (`unit_economics_2026-09.xlsx`), сводный ОПиУ не сохраняет | месяц: Enter — текущий, `1` — прошлый, `ГГГГ-ММ` — любой |
| **`ОПиУ_по_неделям.bat`** | ОПиУ по неделям за весь период свода (`opiu_weekly_2026-01_2026-09.xlsx`) | ничего |
| **`ОПиУ_по_дням.bat`** | ОПиУ по дням одного месяца (`opiu_daily_2026-09.xlsx`) | месяц отчёта |

Все четыре обновляют данные маркетплейсов, поэтому перед запуском отключите VPN. Разрез отчёта — только в колонках: статьи, сопоставление, себестоимость, налог и сверки везде одинаковые.

## Запуск

**Проще всего:** дважды щёлкните **`Обновить_отчёт.bat`** в папке проекта. Скрипт обновит данные всех маркетплейсов и кабинетов по текущий месяц и соберёт один Excel. Готовый файл откроется сам. В нём:
- ОПиУ: свод, по маркетплейсам и по каждому кабинету;
- расчёт себестоимости по каждому заказу;
- товары;
- сверки на листе «Контроль».

Рядом сохраняется и открывается второй файл — **юнит-экономика** по каждому артикулу в разрезе маркетплейсов и кабинетов и реестр для сводных таблиц (см. раздел «Юнит-экономика по артикулам»). В начале `.bat` спрашивает, за какой месяц её собрать:
- **Enter** — текущий месяц → файл `unit_economics_2026-09.xlsx`;
- **ГГГГ-ММ**, например `2026-08` — другой месяц → `unit_economics_2026-08.xlsx`;
- **0** — весь период свода → `unit_economics_2026-01_2026-09.xlsx`.

Основной ОПиУ от выбора месяца не зависит — он всегда собирается за весь период.

Перед запуском отключите VPN, иначе Ozon не ответит. Если VPN всё же включён, отчёт соберётся: кабинеты, по которым API не ответил, возьмутся из кэша последней загрузки. На листе «Контроль» у них будет пометка «Данные из кэша: API не ответил при обновлении».

**В конце работы** в консоли выводится итог:
- **«ГОТОВО. Отчёт: …»** и путь к файлу;
- затем либо **«Ошибок нет — все данные загружены, сверки сошлись»**, либо **«Есть замечания»** со списком. В списке: ошибки загрузки по кабинетам, кабинеты из кэша или не попавшие в отчёт, расхождения сверок, неполная себестоимость, число артикулов без цены. Подробности — на листе «Контроль».

Если отчёт собрать не удалось, в конце будет **«ОШИБКА: отчёт не собран»** с причиной.

То же из PowerShell (Shift + правый щелчок по папке → «Открыть окно PowerShell здесь»):

```
python opiu_all.py
```

| Что нужно | Команда |
|---|---|
| Обновить данные всех маркетплейсов и собрать свод | `python opiu_all.py` |
| Собрать свод из уже скачанных данных, без запросов к API (1–2 минуты) | `python opiu_all.py --from-cache` |
| Другой период свода (по умолчанию — с января 2026 по последний месяц с данными) | `python opiu_all.py --from 2026-03 --to 2026-08` |
| Только некоторые маркетплейсы | `python opiu_all.py --only wb,ym` (ключи: `ozon`, `wb`, `ym`) |
| Своё имя файла | `python opiu_all.py --out свод.xlsx` |
| Открыть Excel после сборки | `python opiu_all.py --open` (так запускает `.bat`) |
| Юнит-экономика за один месяц | `python opiu_all.py --unit-month 2026-08` (без ключа или `--unit-month 0` — за весь период свода) |
| Не собирать файл юнит-экономики | `python opiu_all.py --no-unit` |
| ОПиУ по неделям за весь период свода | `python opiu_all.py --grain week` (так запускает `ОПиУ_по_неделям.bat`) |
| ОПиУ по дням одного месяца | `python opiu_all.py --grain day --period-month 2026-09` (без ключа — текущий месяц; так запускает `ОПиУ_по_дням.bat`) |
| Собрать **только** юнит-экономику | `python opiu_all.py --only-unit` (сводный `opiu_all_*.xlsx` не сохраняется; данные маркетплейсов всё равно загружаются — добавьте `--from-cache`, чтобы взять уже скачанные) |

**Период свода и период загрузки — разные вещи.**
- **Свод** по умолчанию строится с января 2026. Начальный месяц задан в `DEFAULT_FROM` в начале `opiu_all.py`, разово его меняет `--from`.
- **Загрузку** каждый скрипт делает с месяца `period.from` из своего конфига (`*_accounts.json`) по **текущий месяц**. Значение `period.to` в конфиге при запуске через свод не ограничивает загрузку. Если нужен свод за более ранние месяцы, сначала уменьшите `period.from` в конфигах.

**Если файл свода открыт в Excel**, скрипт сохранит новый отчёт рядом, добавив к имени дату и время.

**Время обновления** — сумма времени скриптов маркетплейсов. Ozon и WB обновляются за минуты. Маркет — около 20 минут, если закрытые месяцы уже в кэше, и около 2 часов при первой загрузке.

**Условия:**
- **Ozon:** перед обновлением отключите VPN, иначе API не ответит. Маркетплейс без данных не останавливает сборку: он попадёт на лист «Контроль» с пометкой, а свод соберётся по остальным.
- **Маркетплейс учитывается только с конфигом:** `Ozon/ozon_accounts.json`, `Wildberries/wb_accounts.json`, `YandexMarket/ym_accounts.json`. Кабинеты добавляются в эти же конфиги, оркестратор подхватит их сам.

## Единый план статей

| Статья | Что входит | Ozon | Wildberries | Яндекс Маркет |
|---|---|---|---|---|
| Продажи / Возвраты | Выручка по цене продавца (до скидок, которые компенсирует маркетплейс) | `sale_amount` | цена продавца | реализация, цена без скидок |
| Комиссия маркетплейса | Комиссия, вознаграждение, размещение, агентское вознаграждение | комиссия за продажу | кВВ, выдача на ПВЗ | размещение товара |
| Логистика и доставка | Доставка покупателю, магистраль, миля, обработка отправлений, упаковка | логистика, drop-off, доставка до ПВЗ | «К клиенту при продаже» | доставка покупателю, средняя миля |
| Обратная логистика, отмены и невыкупы | Логистика и обработка отмен, невыкупов, возвратов, брака | обратная логистика | «От клиента…», «Возврат товара продавцу», «К клиенту при отмене» | доставка и обработка невыкупов |
| Эквайринг и платёжные услуги | Эквайринг, перевод платежей, гибкий график, досрочные выплаты, рассрочка | эквайринг, гибкий график выплат | эквайринг | приём и перевод платежа |
| Реклама и продвижение | Продвижение, клики, бусты, отзывы, баллы и лояльность, бейджи | продвижение, клики, отзывы, бейджи | WB Продвижение, лояльность | буст продаж |
| Хранение и складские операции | Хранение, приёмка, размещение, утилизация, маркировка | размещение, утилизация | хранение, приёмка | хранение возвратов |
| Штрафы | Штрафы и сторно, индекс ошибок, нерекомендованные слоты | превышение индекса ошибок, слоты | штрафы МП | — |
| Подписки и прочие услуги | Подписки, страхование, перенос карточек, прочие удержания | Premium, страхование | утилизация (прочие удержания) | подписки |
| Компенсации и прочие доходы | Компенсации, коррекции продаж, доставка за счёт покупателя | товарная компенсация | компенсации при возврате | потерянный заказ |
| Авансы за услуги | Аванс и возврат неиспользованного остатка — движение денег | — | «Баллы за отзывы» | — |

**Результат** = выручка − расходы маркетплейсов + компенсации ± авансы. Для каждого кабинета он в точности равен итогу его собственного отчёта: это проверяется на листе «Контроль».

## Что в Excel

- **Свод.** Все маркетплейсы вместе. Слева после названия статьи идут колонки **«Итого»** и **«% выручки»** (выделены оранжевым и закреплены при прокрутке), дальше месяцы. Под каждой статьёй — разбивка по маркетплейсам. Такая же раскладка на листах маркетплейсов и кабинетов.
- **Сравнение МП.** Статьи за период по маркетплейсам: сумма и % от выручки своего маркетплейса. Здесь видно, например, что комиссия на Маркете 40% выручки, а на Ozon и WB по 27%.
- **Лист маркетплейса.** ОПиУ в единых статьях. Под каждой статьёй — исходные строки отчёта маркетплейса, внизу — справочные данные (оплаты покупателей, баллы, СПП и т. п.).
- **Лист кабинета.** Такой же ОПиУ по одному кабинету. Такие листы появляются, когда у маркетплейса больше одного кабинета. Если кабинет один, лист маркетплейса называется «Маркетплейс — кабинет».
- **Товары.** Артикулы за период: штуки, выручка, себестоимость, подготовка, валовая прибыль, маржа.
- **Себестоимость по заказам.** Расчёт себестоимости построчно по всем кабинетам и маркетплейсам: маркетплейс, кабинет, месяц, дата, номер заказа, артикул, количество, кратность, себестоимость за единицу и себестоимость заказа.
- **Сопоставление статей.** Каждая исходная строка: группа в отчёте маркетплейса, единая статья и сумма. Строки, сопоставленные по ключевым словам (например, новый вид услуги), подсвечены — их стоит проверить.
- **Контроль:**
  - итог в отчёте маркетплейса и в своде;
  - сверка WB с «Итого к оплате»;
  - сверка выплат Маркета;
  - пропущенные дни Ozon;
  - маркетплейсы без данных;
  - покрытие себестоимостью и артикулы без цены.

  Всё, что не OK, подсвечено.

## ОПиУ по неделям и по дням

Тот же ОПиУ и те же листы, что в месячном отчёте, — меняются только колонки.

- **По неделям** — `ОПиУ_по_неделям.bat` или `python opiu_all.py --grain week`. Колонки — недели **пн–вс**, подпись вида `14.09–20.09`, за весь период свода. Файл `opiu_weekly_<от>_<до>.xlsx`.
- **По дням** — `ОПиУ_по_дням.bat` или `python opiu_all.py --grain day --period-month 2026-09`. Колонки — дни месяца с днём недели: `15.09 пн`. Файл `opiu_daily_<ГГГГ-ММ>.xlsx`. Дни без данных в конце месяца (месяц ещё не кончился) не показываются.

**Откуда берутся дни.** Маркетплейсы запускаются с ключом `--grain day`, то есть выгружают ОПиУ по датам, а свод уже складывает дни в недели или показывает их по одному:
- **Ozon** — дата начисления;
- **Wildberries** — `rrDate`, дата строки отчёта о реализации;
- **Яндекс Маркет** — дата услуги, доставки, приёмки возврата или невыкупа. Если дата строки выходит за месяц её отчёта о реализации, она прижимается к границе месяца — сумма по дням всегда равна месяцу отчёта, как в ОПиУ по месяцам.

Сумма дней месяца в дневном отчёте совпадает с колонкой этого месяца в обычном ОПиУ — проверено построчно.

**Про крайние недели.** Неделя может захватывать дни соседних месяцев, поэтому итог недельного отчёта за период немного отличается от месячного: в первую неделю января попадают дни декабря. В подзаголовке листа об этом есть пометка.

**Чего в этих отчётах нет.** Юнит-экономика и файл `cost_missing.csv` считаются за календарные месяцы, поэтому при `--grain week` и `--grain day` не собираются и не перезаписываются — их даёт обычный запуск `Обновить_отчёт.bat`.

## Прогноз на конец месяца и недели

Если последний период отчёта ещё не закончился, справа от него появляется фиолетовая колонка **«Прогноз на 31.10»**:
- в месячном ОПиУ — прогноз на конец текущего месяца;
- в недельном — на воскресенье текущей недели.

Колонка есть на своде и на листах маркетплейсов и кабинетов. В ней заполнены строки:
- выручка за вычетом возвратов;
- итог по данным маркетплейсов (поступление на р/с);
- себестоимость;
- валовая прибыль;
- подготовка и налог;
- прибыль;
- доли от выручки, включая рентабельность (маржинальность).

В строке 3 листа фиолетовым написано, по какую дату взят факт.

**Как считается.** Отдельно по каждому кабинету, потом суммы складываются:

`прогноз = факт с начала периода по день отсечки + среднедневной темп × дни до конца периода`

- **День отсечки** — последний день, за который у маркетплейса есть данные, но не позже вчерашнего: сегодняшние данные неполные. Если данные WB пришли по 03.10, а Ozon — по 04.10, у каждого своя отсечка. Обе даты указаны в пояснении.
- **Темп** — среднее за день с начала периода, но не меньше чем за 14 последних дней для месяца и 7 для недели. В первые дни месяца темп по 2–3 дням случаен, поэтому добирается конец прошлого месяца.
- **Себестоимость, подготовка и налог** считаются по дням по тем же правилам, что и в факте (`cost.csv`, ставка налога). Затем к ним применяется та же экстраполяция. Прибыль = итог МП + себестоимость + подготовка + налог, маржинальность = прибыль / выручка.

Это линейная экстраполяция: сезонность, акции и дни недели не учитываются. Ориентир по точности — бэктест на сентябре 2026: прогноз от 24.09 дал выручку на 7% ниже факта, потому что последняя неделя месяца продавала быстрее.

Для месячного прогноза нужны дневные данные: после основной загрузки скрипты маркетплейсов ещё раз быстро запускаются из только что обновлённого кэша с `--grain day`. К API повторно не обращаются. В недельном и дневном отчётах дни и так загружаются. В дневном отчёте и юнит-экономике прогноза нет.

## Себестоимость и подготовка — файл `cost.csv`

Файл лежит в корне проекта и в git не попадает (в git есть только пример `cost.example.csv`). Открывайте его в Excel, сохраняйте как **CSV (разделитель — точка с запятой)** в UTF-8.

| Колонка | Что вписать |
|---|---|
| **артикул** | Артикул продавца как в кабинете маркетплейса. Регистр и пробелы не важны: `рт-00028973` = `РТ-00028973` |
| **кратность** | Сколько единиц себестоимости в одной продаже (например, набор из 2 шт. — `2`). По умолчанию `1` |
| **сс_за_ед** | Себестоимость одной единицы, ₽. Дробная часть — через запятую: `1450,50` |
| **подготовка_за_ед** | Подготовка одной единицы к отправке (упаковка, маркировка, сборка), ₽. Если подготовки нет — `0` |
| **действует_с** | Необязательно. Дата `ГГГГ-ММ-ДД`, с которой действует цена. Если цена менялась, добавьте ещё строку с тем же артикулом и новой датой; в ней можно заполнить только изменившуюся колонку — вторая возьмётся из прежней строки. Пусто — цена действует всегда |
| **бренд**, **категория** | Единые бренд и категория артикула — попадают в юнит-экономику. Заполнять вручную нужно не всё: WB отдаёт бренд и предмет в отчёте, и скрипт сам дописывает их в пустые ячейки после каждого запуска. Что осталось пустым (товары только Ozon и Яндекса) — впишите сами: заполненное вручную приоритетнее данных маркетплейса и уже не перезаписывается |
| название, маркетплейсы, продано шт. | Справочно, для удобства заполнения — скрипт эти колонки не читает |

Себестоимость и подготовка хранятся в одном файле (раньше подготовка была в отдельном `prep.csv`, теперь его нет).

**Ozon.** В финансовых данных Ozon нет артикула продавца, только SKU Ozon. Скрипт сопоставляет их сам через справочник товаров (`/v3/product/list` и `/v3/product/info/list`) и сохраняет соответствие в кэш. Справочник обновляется при каждом запуске с API: новые товары подхватываются сами. Для первой загрузки нужен запуск без VPN — подойдёт обычный `Обновить_отчёт.bat` или отдельный скрипт:

```
cd Ozon
python ozon_finance.py
```

Пока справочник не загружен, продажи Ozon идут как «SKU …» и попадают на лист «Контроль» с пометкой «нет себестоимости», а валовая прибыль по Ozon завышена. Об этом же предупреждает подпись на листе «Свод».

## Как считается себестоимость

**Себестоимость продажи = штук × кратность × себестоимость за единицу.** Месяц берётся тот же, что и у выручки:

| | Откуда берутся штуки и артикул |
|---|---|
| Wildberries | только строки с обоснованием «Продажа» и «Возврат»: артикул продавца и количество. «Коррекция продаж», компенсации по программе лояльности, «Добровольная компенсация при возврате» и т. п. товар не двигают — штук и себестоимости по ним нет |
| Яндекс Маркет | отчёт о реализации: ваш SKU, доставлено и возвращено; за текущий месяц — отчёт по заказам |
| Ozon | товары отправления: количество считается как цена продажи ÷ цена продавца за единицу, артикул — из справочника товаров |

- **Возвраты** уменьшают и количество, и себестоимость: товар вернулся на склад.
- **Невыкупы и отмены** себестоимости не создают: продажи не было.
- В ОПиУ добавляются строки **«Себестоимость проданных товаров»** и **«ВАЛОВАЯ ПРИБЫЛЬ»**, а в разделе «Доля от выручки» — себестоимость и валовая маржа в процентах.

## Юнит-экономика по артикулам — `unit_economics_*.xlsx`

Отдельный файл собирается тем же запуском из тех же данных, что и ОПиУ. Листы:

- **Юнит-экономика.** Строка на маркетплейс × кабинет × артикул за период: бренд, категория, продано/возвращено/нетто шт., продажи, возвраты, расходы МП по статьям (комиссия, логистика, обратная логистика, эквайринг, реклама, хранение, штрафы, прочие), компенсации, авансы, «к перечислению», себестоимость, подготовка, налог, прибыль, маржа и значения на 1 шт., **текущие цены** (цена до скидки, скидка %, текущая цена, цена с акциями — средняя, если цен несколько), а в конце — **заказы и остатки**: заказано шт. и ₽, отменено, заказов в день, остаток на складах МП, на своём складе, всего, по себестоимости, запас в днях, в пути к покупателям и возвраты в пути. Строка 2 — итоги по видимым строкам, работает с автофильтром. Артикулы без продаж, но с заказами или остатками, тоже получают строку.
- **Артикулы — все МП.** То же по артикулу суммарно по всем маркетплейсам и кабинетам.
- **Заказы.** Заказы покупателей по месяцу × кабинету × артикулу: заказано, отменено, без отмен (шт. и ₽) — умная таблица «Заказы».
- **Воронка.** Показы, переходы в карточку, добавления в корзину, заказы, выкупы, отмены, возвраты по месяцу × кабинету × артикулу — умная таблица «Воронка». Те же показатели плюс CTR, конверсии в корзину и в заказ, % выкупа, % отмен и % возвратов — колонками на листах юнит-экономики.
- **Цены.** Все товары с ценой на момент обновления (в том числе без продаж): цена до скидки, скидка, текущая цена, цена с акциями и себестоимость + подготовка за шт. из `cost.csv` — умная таблица «Цены».
- **Остатки.** Остатки по артикулу × складу на момент обновления: где товар (склады МП / свой склад / в пути), шт., себестоимость за шт. и остаток по себестоимости — умная таблица «Остатки».
- **Реестр.** Все суммы в плоском виде — умная таблица Excel «Реестр» для сводных таблиц. Строка = маркетплейс × кабинет × месяц × артикул × статья × исходная строка отчёта МП. Колонки: Раздел (Выручка, Расходы МП, Компенсации, Авансы, Себестоимость, Подготовка, Налог, Количество), Статья (единый план статей), Отнесение («прямо» / «без артикула»), Сумма (доходы «+», расходы «−»), Кол-во шт. (только у строк раздела «Количество»).
- **Контроль.** По каждому кабинету сумма реестра = прибыль в ОПиУ; доля расходов МП без артикула; число артикулов без себестоимости; число артикулов без бренда или категории — с их списком, чтобы было понятно, что дозаполнить в `cost.csv`; с какой даты есть заказы и на какой момент остатки и цены.
- **Описание.** Пояснения к колонкам и как построить сводную.

**Бренд и категория.** Колонки «Бренд» и «Категория» на обоих листах юнит-экономики — единые по артикулу во всех маркетплейсах и кабинетах. Источник: заполненное в `cost.csv` (приоритет), иначе данные маркетплейса — сейчас это Wildberries (`brandName` и `subjectName` в отчёте реализации); в финансовых отчётах Ozon и Яндекс Маркета бренда и категории нет, поэтому товары, которые не продаются на WB, размечаются через `cost.csv`. Найденное у WB скрипт дописывает в пустые ячейки `cost.csv`, так что справочник заполняется сам. Если у артикула значение не нашлось нигде, ячейка пустая, а артикул перечислен на листе «Контроль».

**Заказы и остатки.** В прибыль и реестр не входят — это спрос и товарный запас рядом с финансовыми показателями.
- *Заказы* — по дате заказа, по цене продавца со скидкой продавца; отменённые показаны отдельно. Источники: WB — статистика заказов (`/api/v1/supplier/orders`), Ozon — отправления FBO и FBS, Яндекс Маркет — отчёт по заказам. WB и Маркет отдают заказы только примерно за последние 90 дней, поэтому история копится в кэше скриптов при каждом обновлении: за более ранние месяцы заказов может не быть — дата начала данных указана на листе «Контроль».
- *Остатки* — на момент запуска (не на конец месяца). WB: склады WB и «в пути» из отчёта об остатках + свои склады FBS; Ozon: FBO, FBS, rFBS (`/v4/product/info/stocks`); Маркет: годные остатки по магазинам (FBY — склад Маркета, FBS/Express — свой склад). При запуске с `--from-cache` берутся остатки прошлой загрузки.
- *Цены* — установленные в кабинете на момент запуска (не средняя цена продаж — она в колонке «Цена за 1 шт»). WB: цена и цена со скидкой продавца по размерам (`discounts-prices-api /api/v2/list/goods/filter`; цены с СПП в API нет); Ozon: `price`, `old_price` и цена с акциями (`/v5/product/info/prices`); Маркет: базовые цены кабинета (`/v2/businesses/{id}/offer-prices`), если их нет — цены магазинов. С `--from-cache` — цены прошлой загрузки. Артикул, у которого есть только цена (нет продаж, заказов и остатков), отдельной строки в юнит-экономике не получает — он есть на листе «Цены».
- *Заказов в день* = заказано без отмен / число дней периода с данными о заказах; *Запас, дней* = (склады МП + свой склад) / заказов в день.
- Нужные доступы токенов: WB — категории «Статистика», «Аналитика», «Маркетплейс», «Контент», «Цены и скидки» (помимо «Финансов»); Ozon — чтение отправлений и товаров; Маркет — доступ к товарам/остаткам (подходит «Просмотр всех данных»). Если доступа нет, отчёт всё равно собирается, а в консоли будет «ОШИБКА: заказы/остатки/цены не получены».

**Воронка продаж.** Источники: WB — воронка продаж (`/api/analytics/v3/sales-funnel/products`, до 365 дней истории), Ozon — `/v1/analytics/data` (SKU × месяц), Яндекс Маркет — отчёт «Аналитика продаж» (без подписки — только 90 дней, история копится в кэше). Ограничения: WB не отдаёт **показы** без подписки «Джем» — у WB есть переходы в карточку, корзина, заказы, выкупы и отмены, а CTR пустой; Ozon отдаёт показы и корзину только с Premium — без неё скрипт сам переключится на заказы/выкупы/отмены/возвраты. Конверсии (лист «Воронка» — формулами Excel, листы юнит-экономики — значениями): CTR = переходы / показы; карточка → корзина = в корзину / переходы; корзина → заказ = заказано / в корзину; карточка → заказ = заказано / переходы; сквозная = заказано / показы; выкуп = выкуплено / заказано; выкуп по завершённым = выкуплено / (выкуплено + отменено + возвращено); отмены = отменено / заказано; возвраты = возвращено / выкуплено; средняя цена заказа = заказано ₽ / заказано шт. В строке итогов проценты считаются из сумм и только по строкам, где маркетплейс даёт и числитель, и знаменатель (скрытые колонки-помощники), поэтому они верны при любом фильтре. Если Ozon без Premium молча отдаёт не все метрики, скрипт это распознаёт и берёт меньший набор. Выкупы считаются по дате выкупа, поэтому в отдельном месяце % выкупа может быть больше 100%. Первая загрузка воронки WB занимает несколько минут (закрытые месяцы потом берутся из кэша), отчёт Маркета генерируется 2–8 минут.

**Сводная таблица:** встаньте в таблицу на листе «Реестр» → Вставка → Сводная таблица. Например: строки — Артикул, столбцы — Раздел, значения — Сумма, ₽; фильтры — Маркетплейс, Кабинет, Месяц.

**Как расходы относятся к артикулам.** Прямо, по данным маркетплейса:
- Wildberries — артикул продавца в каждой строке отчёта реализации;
- Ozon — SKU у каждого товара отправления (выручка, комиссия, логистика) и у товарных сборов; артикул — из справочника товаров;
- Яндекс Маркет — ваш SKU в отчётах об услугах и реализации; услуги по заказу без SKU (обработка заказа) — на товар заказа, если он в заказе один.

Начисления, которые маркетплейс к товару не относит (реклама по кампаниям, удержания WB, подписки, часть хранения и штрафов, гибкий график выплат Ozon), **не распределяются**: они собраны в строку **«Без артикула»** каждого кабинета (подсвечена). Поэтому прибыль по артикулам — до этих расходов; прибыль кабинета = сумма по артикулам + «Без артикула».

## Как считается подготовка товара

Так же, как себестоимость: **штук × кратность × стоимость подготовки**, месяц тот же, что у выручки, возвраты сторнируются. Пустая ячейка `подготовка_за_ед` — артикул считается незаполненным и попадает в `cost_missing.csv`.

## Налог с выручки

Ставка задаётся **в настройках маркетплейса** — ключ `tax_percent` в его конфиге:

```json
{
  "period": { "from": "2025-09", "to": "2026-09" },
  "tax_percent": 7,
  "accounts": [
    { "name": "ЕвроЗоо", "client_id": "…", "api_key": "…", "enabled": true }
  ]
}
```

- Ставка применяется к **фактической цене покупки после скидок маркетплейса**; возвраты уменьшают базу:
  - Wildberries — «Вайлдберриз реализовал» (`retailAmount`), то есть цена после СПП;
  - Ozon — сумма, оплаченная покупателем (`sale_price`), без доплаты Ozon за его скидки;
  - Яндекс Маркет — цена с учётом скидок (фактическая оплата покупателя).
- Если в кэше старая выгрузка без этой базы, налог считается по-старому — от выручки по цене продавца.
- Проверка: `python tests/test_tax_purchase_base.py`.
- Можно задать свою ставку отдельному кабинету: добавьте `"tax_percent": 6` внутрь его блока в `accounts`. Значение кабинета важнее общего.
- Сейчас ставки заданы по кабинетам: ООО «Еврозоо» (Ozon, WB, Яндекс) — **5%**, все ИП — **7%** (2% налог + 5% НДС). Общий `tax_percent` = `0`, поэтому новый кабинет без своей ставки сразу будет помечен на «Контроле».
- При ставке `0` строки налога в отчёте нулевые, а на листе «Контроль» стоит пометка «укажите tax_percent».

## Итог отчёта

```
ИТОГО: РЕЗУЛЬТАТ ПО ДАННЫМ МАРКЕТПЛЕЙСОВ   выручка − расходы МП + компенсации ± авансы
− Себестоимость проданных товаров
= ВАЛОВАЯ ПРИБЫЛЬ (после себестоимости)
− Подготовка товара, ₽
  Подготовка товара, % от выручки
− Налог с выручки, ₽
  Налог с выручки, % от выручки
= ПРИБЫЛЬ (после себестоимости, подготовки и налога)
```

Подготовка и налог выводятся **всегда** — даже если ставка ещё не задана или подготовка в `cost.csv` не заполнена (тогда там нули). Сумма налога считается от фактической цены покупки, а «% от выручки» — это отношение налога к выручке по цене продавца за вычетом возвратов; поэтому процент может быть меньше ставки. Проценты показаны со знаком минус, как и суммы.

В разделе «Доля от выручки» к процентам добавляются себестоимость, подготовка, налог и итоговая рентабельность.

**Лист «Товары»:** по каждому артикулу за период — штуки, выручка, себестоимость, валовая прибыль и маржа. Сначала строка «Все маркетплейсы» (выделена серым), под ней разбивка по маркетплейсам. Есть автофильтр: можно отсортировать по марже и найти убыточные позиции.

**Лист «Себестоимость по заказам»:** каждая строка — артикул в заказе. Себестоимость заказа = количество × кратность × себестоимость за единицу из `cost.csv`, действующая в месяце продажи. Номер заказа: Ozon — номер отправления, Wildberries — `srid` из отчёта о реализации, Яндекс Маркет — номер заказа. Дата: Ozon — дата начисления, WB — дата строки отчёта, Яндекс — дата доставки (для возвратов — дата приёмки возврата). Возвраты идут с отрицательным количеством и уменьшают себестоимость. Если у артикула нет цены, в последней колонке стоит «нет в cost.csv» (оранжевым). В строке «Итого» над таблицей стоят формулы `ПРОМЕЖУТОЧНЫЕ.ИТОГИ`, поэтому при фильтре по кабинету, месяцу или артикулу суммы пересчитываются. Сумма листа по каждому кабинету сверяется со строкой «Себестоимость» в ОПиУ на листе «Контроль»: разница должна быть 0.

**На листе «Контроль»** по каждому кабинету видно, какая доля выручки закрыта себестоимостью. Ниже перечислены артикулы без себестоимости с выручкой и штуками.

**Новые товары.** Если у артикула нет себестоимости или подготовки, скрипт выписывает его в `cost_missing.csv` — с маркетплейсом, штуками, выручкой и средней ценой продажи, а также с колонками «бренд» и «категория» (их тоже можно заполнить там — перенесутся в `cost.csv` вместе с ценами). Уже известные цены там подставлены, заполнять нужно только пустые ячейки. Запустите свод ещё раз: цены сами перенесутся в `cost.csv`, а `cost_missing.csv` удалится, когда все товары будут с ценами. Через `cost_missing.csv` дописываются только пустые ячейки — уже заполненную цену меняйте в самом `cost.csv`. Если в `cost_missing.csv` окажется цена, которую не удалось перенести, скрипт перед перезаписью сохранит копию `cost_missing_backup_….csv`.

## Как поменять сопоставление

Правила лежат в начале `opiu_all.py`:
- `GROUP_MAP` — группа отчёта маркетплейса → единая статья;
- `RETURNS_LABEL` — какие строки логистики относятся к обратной логистике;
- `GROUP_KEYWORDS` — запасные правила для новых групп.

Детальную классификацию видов услуг внутри маркетплейса задают сами скрипты: для Ozon это `KEYWORDS` в `Ozon/ozon_finance.py`.

## Кратность продажи на маркетплейсе

В юнит-экономике колонка **«Кратность на МП, шт»** (сразу после категории) — сколько единиц в одном товаре по карточке маркетплейса (набор 15 паучей — 15). Источники: Ozon — характеристика «Единиц в одном товаре» (если пусто — «Количество заводских упаковок»), Wildberries — «Количество предметов в упаковке» (если пусто — «Количество в упаковке (шт.)»), Яндекс Маркет — «Количество упаковок в товаре». Значение текущее, загружается при обновлении без `--from-cache`. Лист **«Кратность»** — все товары с кратностью и сравнение с колонкой `кратность` в `cost.csv` (расхождения «НЕТ» — сверху). В расчёт себестоимости кратность МП не подставляется — используется `cost.csv`.

## Юнит-экономика по неделям

`Юнит_по_неделям.bat` (= `python opiu_all.py --unit-weekly --open [--from ГГГГ-ММ]`) собирает `unit_economics_weekly_<от>_<до>.xlsx`: строка — неделя × маркетплейс × кабинет × артикул, колонки **Год, Месяц, Неделя (ISO), Даты**. Неделя на стыке месяцев делится на две строки (28.09–30.09 и 01.10–04.10), поэтому фильтр по месяцу даёт ровно месяц, а суммы сходятся с месячной юниткой. Колонки: продажи, расходы МП, себестоимость, подготовка, налог, прибыль, заказы и кратность; остатки, цены и воронка — только в месячной юнитке. Лист «Контроль» сверяет прибыль по кабинетам с ОПиУ.
