# Сервис автоматизации WB и отчётности «Честный знак»

## Цель MVP

Единый сервис для:

1. получения вопросов и отзывов из кабинетов Wildberries;
2. подготовки и (после включения режима автопубликации) отправки ответов;
3. загрузки комплектов отчётов «о пострадавших товарах» Честного знака;
4. формирования сводки по складам, отчётам и товарам;
5. ведения журнала всех входящих данных, решений и отправок.

## Предлагаемые границы первой версии

- адаптер WB API с несколькими кабинетами;
- режимы `draft` и `auto` для ответов;
- правила безопасности: не отвечать повторно, не публиковать запрещённые категории ответов, отправлять спорные случаи на ручную проверку;
- импорт PDF-отчётов Честного знака из папки или через веб-загрузку;
- извлечение метаданных PDF и сохранение оригиналов;
- сводный отчёт в XLSX/CSV и просмотр в веб-интерфейсе;
- повторяемые фоновые задачи и журнал ошибок.

## Предварительная архитектура

```text
WB API ──> Sync workers ──> Normalized DB ──> Rules/LLM ──> Draft/Publish
                                      └────> Audit log

PDF + signature + MЧД ──> Report importer ──> Report DB ──> XLSX/CSV/dashboard
```

Базовый стек по умолчанию: Python, FastAPI, SQLAlchemy, SQLite для локального запуска (с возможностью перейти на PostgreSQL), React/Vite или серверные HTML-шаблоны для первого интерфейса. Точный выбор фиксируется после ответов по развёртыванию.

## Что нужно подтвердить

- количество кабинетов и способ хранения WB-токенов;
- автоматическая публикация или согласование черновиков;
- правила и тон ответов;
- состав сверки по поставкам и каналы доставки отчётов;
- среда запуска;
- предпочтительный стек.

## Найденные исходные данные

В `tmp_reports/` находятся 10 комплектов Честного знака. Каждый комплект содержит PDF `damaged-product-report-*.pdf`, `mchd.zip` и `signature.sig`. Эти файлы считаются тестовыми/исходными данными и не изменяются.

## Подтверждённые решения

- первый запуск: один кабинет, токен в `.env`;
- конфигурация сразу допускает добавление кабинетов через JSON-массив `WBOPS_CABINETS_JSON`;
- ответы сначала сохраняются как черновики, без публикации;
- тексты строятся шаблонами, без LLM;
- запуск: веб-сервис FastAPI;
- хранилище MVP: SQLite (`data/wbops.sqlite3`), интерфейс хранения оставлен отдельным для последующего PostgreSQL;
- отчёт Честного знака в первой версии: PDF-сводка по складам, номерам отчётов, товарам и количеству; сверка с поставками WB — отдельное расширение.
- автосинхронизация выключена по умолчанию, интервал и состояние сохраняются в SQLite;
- публикация требует одновременно `WBOPS_DRY_RUN=false` и ручного подтверждения конкретного черновика;
- Excel-экспорт формирует листы `Сводка` и `Товары`.
- жалобы не отправляются через API: WB отключил эти методы; сервис формирует очередь ручной проверки для отзывов 1–2 звезды с явными признаками спама, нецензурной лексики, угроз или политического контекста;
- низкая оценка без доказуемого нарушения автоматически помечается `not_eligible`.
- база знаний вопросов собрана из 197 исторических пар «вопрос–ответ»; точное совпадение по WB ID и тексту может использовать исторический ответ, новые формулировки проходят через безопасные тематические шаблоны.
